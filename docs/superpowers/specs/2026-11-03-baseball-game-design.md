# 삼성 라이온즈 야구게임 — 설계 문서

작성일: 2026-11-03

## 1. 무엇을, 왜

혼자 폰으로 즐기려고 만드는 야구게임이다. 팔 생각은 없다. **해보면 재미있어야** 하고, 그래픽은 **리얼하고 섬세한 2D 일러스트**여야 한다. (2026-11-04 스파이크 3을 해본 뒤 사용자가 결정)

- 내 팀은 **삼성 라이온즈**다. 상대 팀은 **실제 KBO 구단**이고, 컴퓨터가 맡는다.
- 9이닝 경기 한 판을 한다. 수비 때는 내가 **투수**가 되어 직접 던지고, 공격 때는 내가 **타자**가 되어 직접 친다.
- 재미의 핵심은 **던지고 치는 손맛**이다. 타이밍을 맞췄을 때 확실한 보상(소리, 화면 효과, 진동)이 와야 한다.

## 2. 목표 / 하지 않을 것 / 실패 기준

**목표**
- 폰 브라우저에서 링크만 열면 설치 없이 바로 플레이할 수 있다.
- 안드로이드와 아이폰에서 모두 정상 동작한다.
- 터치 타격과 드래그 투구가 손에 붙는다.
- 선수 능력치 차이가 플레이에서 체감된다. 에이스는 던지기 편하고, 강타자는 멀리 날린다.

**하지 않을 것**
- 시즌 모드, 트레이드, 선수 육성, 온라인 대전, 계정, 결제
- 수비수나 주자를 직접 조작하는 것 (전부 자동)
- 3D 그래픽, 실사 사진/모션캡처 수준 그래픽

**실패 기준** (돌아가긴 해도 이러면 실패다)
- 타격 타이밍이 운처럼 느껴지거나, 터치 반응이 늦어서 내가 맞춘 타이밍이 무시되는 느낌이 든다.
- 투구가 지루하다. 어디에 어떤 공을 던지든 결과가 비슷하다.
- 한 판이 너무 길어서 끝까지 하기 싫다.
- 폰 화면에서 버튼이 작거나, 손가락이 공을 가려서 플레이가 안 된다.

## 3. 제약

- **플랫폼**: 모바일 웹브라우저(안드로이드 크롬, 아이폰 사파리)에서 세로 화면 기준으로 동작한다. 설치는 없다.
- **진동**: 안드로이드에서만 쓴다(Vibration API). **아이폰 진동은 포기**하고 타격음과 화면 흔들림으로 대신한다. (사용자 결정)
- **실명 사용**: 개인용이라 KBO 선수 실명을 쓴다. 외부에 배포하지 않는다.
- **저장**: 서버 없이 폰 브라우저 저장소만 쓴다.
- **배포**: **GitHub Pages**에 올린다. (사용자 결정) 무료 GitHub Pages는 공개 저장소가 필요하므로 저장소와 페이지 주소는 공개 상태다. 주소를 알아야 들어올 수 있는 정도의 비공개만 기대한다. 빌드 과정 없이 정적 파일만으로 올라가는 구조가 가장 간단하다.

## 4. 사용자가 정한 것

### 4.1 경기 구조
- 삼성 라이온즈 vs 컴퓨터가 맡은 KBO 구단 1팀, **9이닝 정규 경기**다.
- 삼성이 수비할 때는 내가 투수, 공격할 때는 내가 타자다. 매 투구와 매 타석을 직접 한다.
- 경기 전에 상대 팀을 고른다(나머지 9개 구단 중 하나).

### 4.1-1 그래픽과 시점 (스파이크 2~3 피드백으로 확정)
- **리얼하고 섬세한 2D 일러스트**: 관절 단위로 움직이는 선수(비율 잡힌 몸, 유니폼 주름/명암, 헬멧·모자·글러브·방망이), 관중석·광고판·펜스·잔디 줄무늬·흙·라인이 있는 구장. 스파이크 3보다 더 고도화한다(명암, 하이라이트, 디테일, 부드러운 동작).
- 유니폼은 구단 색을 따른다(삼성 홈: 흰색+파랑, 원정팀: 회색 원정 유니폼+구단 색). 로고는 그리지 않는다.
- **타격 시점**: 포수 뒤에서 투수를 본다. 마운드 위 상대 투수가 와인드업(세트 → 다리 들기 → 팔 뒤로 → 릴리스 → 팔로스루)하고, 공은 투수 손에서 출발한다.
- **투구 시점**: 내 투수 뒤에서 홈플레이트를 본다. 내 투수 뒷모습(이름·등번호), 포수, 심판, 타자가 보인다. 포수 미트가 조준점을 따라온다.
- **타구 화면**: 공이 인플레이되면 위에서 내려다본 경기장으로 전환해 타구 궤적(높이·그림자), 수비수 움직임, 비거리를 보여준 뒤 결과를 표시한다.

### 4.2 타격
- 투수가 던진 공이 날아온다. **타이밍에 맞춰 화면을 터치하면 스윙**한다.
- 공에 맞으면 **안드로이드는 진동**이 온다. 아이폰은 타격음과 화면 흔들림으로 대신한다.
- 타이밍이 정확할수록 좋은 타구가 나온다.
- 타자 능력치를 반영한다. 파워가 높으면 멀리 날아가고, 컨택이 높으면 타이밍 허용 구간이 넓다. (능력치 연결 방식은 Claude의 제안이고, 사용자가 동의했다.)

### 4.3 투구
순서는 다음과 같다.
1. 스트라이크존 위의 **조준점을 손가락으로 드래그**해서 공이 갈 위치를 정확히 정한다.
2. 그 투수가 가진 구종 중에서 **던질 구종을 고른다.**
3. **타이밍을 맞추면 제구가 잘 된다.** 공이 조준점 근처로 가고, 어긋나면 크게 벗어난다.
- 투수 기량이 좋을수록 **구속이 잘 나오고 제구가 쉽다**(타이밍 성공 구간이 넓다).
- **난이도 기준(스파이크 3에서 확정)**: 성공 구간 폭 = `0.07 + 제구/100 × 0.12`(게이지 길이 대비), 게이지 왕복 0.9초. 성공 구간 안에도 더 좁은 "완벽" 구간이 있고, 가운데에서 멀수록 공이 미트에서 멀어진다.
- **지칠수록 제구가 어려워진다**: 체력의 약 절반을 넘기면 피로가 쌓이기 시작해, 성공 구간이 최대 60% 좁아지고 게이지가 빨라지며 공이 더 흩어지고 구속이 떨어진다.
- **스트라이크 판정**: 공이 존에 조금이라도 걸치면 스트라이크다(공 중심이 아니라 공 테두리 기준).
- 타이밍 입력 방식은 Claude가 제안했다. 화면의 게이지가 왕복하고, 가운데 구역에서 터치하면 성공이다. 플레이해보고 조정한다.
- 컴퓨터 타자는 공의 코스, 구종, 구속에 따라 스윙 여부와 결과가 달라진다. 그래야 어디에 무슨 공을 던지느냐가 의미를 가진다.

### 4.4 감독 기능 (이 두 가지만)
- **타순 짜기**: 경기 전에 삼성 타순을 정한다. 다음 경기를 위해 폰에 저장한다.
- **투수 교체**: 경기 중에 불펜 투수로 바꾼다. 투수는 던질수록 지쳐서 구속과 제구가 떨어진다. 그래야 교체할 이유가 생긴다. (지침 효과는 Claude의 제안이고, 사용자가 동의했다.)

### 4.5 선수 데이터
- 10개 구단의 실제 선수를 넣는다. 팀마다 주전 타자 9명 이상, 선발투수 1명 이상, 불펜투수 몇 명을 둔다.
- 2026 시즌 명단 기준이지만, Claude가 아는 정보로 만들기 때문에 이적이나 부상이 빠져 있을 수 있다.
- 능력치(타자: 파워·컨택 등 / 투수: 구속·제구·구종 목록·체력)는 실제 성적과 평판을 보고 대략 매긴다.
- 명단과 능력치는 **코드와 분리된 데이터 파일**에 두어서 사용자가 직접 고칠 수 있게 한다.

## 5. Claude가 정한 것 (사용자가 들었고, 반대하지 않음)

- **수비와 주루는 자동이다.** 타구가 맞으면 타구 질(타이밍, 파워, 방향)을 보고 확률로 결과(아웃, 안타, 장타, 홈런 등)를 정한다. 주자 진루도 규칙에 따라 자동으로 처리한다.
- **이닝 수는 경기 전에 3 / 5 / 9 중에서 고른다. 기본값은 9이닝이다.** 처음부터 넣는다. 9이닝을 직접 다 하면 한쪽당 약 140구라 20분을 훌쩍 넘기 쉽기 때문이다. (검토 후 Claude가 정함)
- **명단과 능력치는 PC에서 데이터 파일을 고쳐 다시 올리는 방식**으로 수정한다. 폰 안에 편집 화면은 만들지 않는다. (검토 후 Claude가 정함)
- 화면 구성은 4.1-1을 따른다. 그림은 외부 이미지 없이 캔버스에 코드로 그린다(Claude의 결정: 파일 하나로 배포 가능, 유니폼 색을 구단별로 바꾸기 쉬움).
- **소리**: 미트에 꽂히는 소리, 타격음, 관중 함성 정도만 넣는다.
- **저장**: 짜놓은 타순만 저장한다. 진행 중인 경기는 저장하지 않는다.

## 6. 만드는 사람에게 맡기는 것

- 기술 선택(프레임워크 여부, 캔버스나 DOM 등). 단 폰 브라우저에서 가볍고 터치 반응이 빨라야 한다.
- 타구 결과 확률표, 컴퓨터 타자와 투수의 AI, 난이도 수치
- 화면 배치, 색, 효과음 출처(직접 합성 가능)
- 스코어보드, 이닝 전환, 경기 종료 화면 등 경기 진행 UI의 세부 형태
- 연장전 처리 방식 (KBO 규정을 따르되 단순화해도 된다)
