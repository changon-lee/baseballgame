# 육성모드 설계

2026-11-12 · 상태: 사용자 승인 대기

## 1. 무엇을, 왜

**무엇을 만드나**

- 지금 게임에는 시즌모드(커리어)와 1:1 대결모드가 있다. 여기에 세 번째 모드인 **육성모드**를 더한다.
- 플레이 흐름은 이렇다.
  1. 삼성 실제 선수 한 명(타자 또는 투수)을 고른다.
  2. 경기와 경기 사이에 **훈련 하나 또는 휴식**을 고른다.
  3. 경기에서는 **그 선수가 나오는 장면만** 직접 한다.

**왜 만드나**

- 지금의 성장은 "경기하다 보면 경험치가 쌓여 능력치가 조금 오르는" 수준이라 고민할 거리가 없다.
- 육성모드에서는 다음 선택이 선수를 만든다.
  - 어떤 능력치를 키울지
  - 피로를 감수하고 더 훈련할지
  - 어떤 특성을 노릴지
- 그 결과가 경기 성적(안타·홈런, 투수라면 잘 막기)으로 느껴져야 한다.

**성공의 모습**

- 사용자의 말: "내가 타자면 안타를 많이 치고 홈런을 많이 치고 이런 게 좋은 거지."
- 사용자의 말: "내 선수 성적이 좋을수록 팀의 승과 순위도 좋은 거지."
- 판단 기준은 능력치 숫자가 아니라 **내 선수의 성적과 팀 순위**다.

## 2. 목표 · 하지 않을 것 · 실패로 보는 것

**목표**

- 선수 한 명을 끝없이 키운다.
- 저장 슬롯이 여러 개라 여러 선수를 따로 키울 수 있다.
- 경기는 짧다.
  - 타자: 한 경기 약 5분. 내 타석만 직접 한다.
  - 투수: 5~10분. 선발이면 강판될 때까지, 마무리면 9회만 던진다.
- 훈련 선택에 피로라는 대가가 있다. 피로가 차면 훈련을 못 한다.
- 컨디션(기세)이 있다. 잘하면 오르고, 못하거나 지치면 떨어지며, 경기력에 영향을 준다.
- 특성이 있다. 훈련이나 경기 활약으로 얻는다.
- 팀 승패와 순위를 기록한다.

**하지 않을 것**

- 시즌모드와 대결모드는 동작, 저장 데이터, 밸런스를 하나도 바꾸지 않는다.
- 육성한 선수를 시즌모드나 대결모드 로스터로 옮기지 않는다. 사용자 결정: "육성모드 안에서만".
- 새 조작 방식을 만들지 않는다. 투구, 타격, 수비 조작은 기존 경기 화면 그대로다.
- 새 그림이나 소리 에셋을 만들지 않는다. 기존 에셋만 쓴다.
- 능력치가 최대치에 닿은 뒤를 위한 별도 목표는 넣지 않는다. 사용자 결정: "그냥 계속 하게 둬".
- 무작위 이벤트(스토리 사건)는 이번에 넣지 않는다. 특성은 훈련과 경기로만 얻는다.

**실패로 보는 것** (동작은 해도 실패다)

- 시즌모드나 대결모드의 기존 테스트(balance, season, career, versus 등)가 하나라도 깨지거나, 같은 씨앗으로 돌린 결과가 달라진다.
- 내 장면이 오기까지 오래 기다려야 한다. 내 장면과 내 장면 사이의 자동 진행은 몇 초 안에 끝나야 한다.
- 훈련이 무의미하다. 몇 시즌 키워도 성적 차이가 느껴지지 않는다.
- 반대로 훈련 몇 번에 선수가 사기가 된다.
- 특성이나 컨디션 효과가 너무 커서 조작 실력보다 숫자가 결과를 정한다.

## 3. 지켜야 할 조건

- 빌드 없는 바닐라 ES 모듈이고, 외부 라이브러리는 쓰지 않는다. 저장은 localStorage다.
- 규칙 로직은 `js/core`에 둔다. 순수 함수이고 rng를 주입받는다.
  - 테스트를 먼저 쓴다(`tests/*.test.mjs`).
- 화면은 `js/ui`에 둔다.
- 폰 세로 화면과 터치가 기준이다. 문구는 한국어 "~해요" 말투다.
- 육성모드 저장은 **별도 키**를 쓴다: `baseball.raise.v1`.
  - 기존 키(`baseball.career.v1`, `bb.prefs`, `bb.versus`, 타순 키)는 읽기만 할 수 있고 쓰지 않는다.
  - 예외: 기존 화면 설정 `bb.prefs`(난이도, 수비 조작 등)는 기존처럼 공유한다.
- 작업은 `build` 브랜치에서 한다. main에는 사용자가 로컬에서 확인하고 "배포"라고 하기 전까지 push하지 않는다.
- 끝내기 전에 전체 테스트를 통과시킨다.
  - 명령: `node --test "tests/*.test.mjs"`
  - 로컬 확인 서버: `python serve.py 8000`

## 4. 정해진 설계 (사용자 결정)

| 항목 | 결정 |
|---|---|
| 키우는 대상 | 삼성 로스터의 실제 선수 1명. 타자 12명, 투수 9명 중에서 고른다 |
| 길이 | 끝없음. 능력치가 최대치에 닿아도 계속 할 수 있다 |
| 슬롯 | 여러 개. 슬롯마다 다른 선수를 따로 키운다 |
| 경기 장면 | 타자: 내 타석만 직접 한다. 너무 못하면 교체된다. 투수: 선발은 강판까지, 마무리는 마무리 등판만 한다 |
| 경기 사이 | 훈련을 골라 능력치를 올린다. 피로가 쌓이고, 다 차면 더 못 한다 |
| 특성 | 넣는다. 훈련이나 경기 활약으로 생긴다 |
| 컨디션(기세) | 넣는다. 플레이 결과에 따라 오르내린다 |
| 다른 모드로 가져가기 | 안 한다 |
| 팀 성적 | 승패와 순위도 기록한다. 내 선수 성적이 팀 성적으로 이어진다 |

## 5. 세부 설계

★는 설계자가 정한 것이다. 사용자가 바꿀 수 있다.

### 5.1 진입과 슬롯

- 시즌 허브 홈 탭에 "🤝 친선 경기", "📱 1:1 대결"과 나란히 **"🌱 육성모드"** 버튼을 둔다(`js/ui/hub.js`).
  - `main.js`에 `raise` 콜백을 더한다.
  - ★ 개발용 주소 `#raise`도 둔다.
- ★ 슬롯은 3개다. 슬롯 화면에는 칸마다 다음을 보여 준다.
  - 선수 이름, 포지션 또는 보직, 몇 년 차 몇 경기째인지
  - 이번 시즌 성적 한 줄
- 빈 슬롯은 "새로 키우기"다.
- 슬롯을 지울 수 있다. 확인 단계를 한 번 거친다.
- 새로 키우기에서는 삼성 선수 목록이 나온다.
  - `js/data/rosters.js`의 원래 능력치를 보여 준다. 시즌모드 성장분은 반영하지 않는다.
  - 타자와 투수 탭으로 나눈다.
- ★ 같은 선수를 두 슬롯에서 따로 키울 수 있다.

### 5.2 하루 흐름

- 하루는 **선택 1번 → 경기 1번**이다.
- 육성 허브 화면에는 다음이 있다.
  - **선수 카드:** 능력치, 컨디션, 피로 막대, 특성
  - 다음 경기 정보: 상대, "2027 시즌 5/27경기"
  - **오늘의 선택:** 훈련 목록과 휴식
- 선택을 하면 결과를 짧게 보여 준다(능력치 +1, 피로 +20 등). 그다음 "경기 시작" 버튼이 나온다.
- 선택을 건너뛰고 바로 경기에 나갈 수도 있다. 그러면 휴식보다 회복이 적다(5.4).
- 경기가 끝나면 결과 화면을 보여 주고 허브로 돌아간다.
- 결과 화면에 나오는 것:
  - 내 기록 한 줄
  - 팀 승패
  - 컨디션 변화
  - 경기 경험치로 오른 능력치
  - 새로 얻은 특성
- ★ 매 선택과 매 경기가 끝날 때마다 바로 저장한다.
  - 경기 도중에 나가면 그 경기는 없던 것이 된다. 시즌모드와 같은 방식이다.

### 5.3 훈련

- ★ 훈련 종류: 일반 훈련은 능력치마다 하나씩 있고, 특훈은 특성을 노리는 훈련이다.

| 대상 | 일반 훈련(능력치) | 특훈(특성용) |
|---|---|---|
| 타자 | 파워 · 컨택 · 선구안 | 득점권 대비 · 좌투수 대비 · 초구 공략 |
| 투수 | 구속 · 제구 · 체력 | 위기 대비 · 좌타자 대비 · 결정구 |

- 일반 훈련은 그 능력치에 경험치를 크게 쌓는다.
  - ★ 기존 `growth.js`의 "12점마다 +1" 구조를 쓴다.
  - 능력치가 높을수록 덜 오른다.
  - 목표: 70대에서 훈련 2~3번에 +1, 90 이상에서 5~6번에 +1.
- 상한은 기존과 같다: 타자 능력치·제구·체력 99, 구속 162.
- 특훈은 능력치를 조금만 올린다. 대신 그 특성의 **진행도**를 쌓는다(5.6).
- 피로 비용(★ 처음 값, 숫자만 조정하면 되게 한 곳에 모은다):
  - 일반 훈련 +20
  - 특훈 +30
  - **피로 + 비용이 100을 넘는 훈련은 고를 수 없다.** 버튼을 흐리게 하고 "너무 지쳤어요"라고 표시한다.

### 5.4 피로

- 피로는 0~100이고, 내 선수만 따로 갖는다.
- ★ 변화량:

| 일 | 피로 |
|---|---|
| 휴식 | −45 |
| 선택 없이 경기에 나감 | −10 (자연 회복) |
| 타자로 경기 출전 | +5 |
| 투수 등판 | 던진 공 수 × 0.4 (선발 90구면 +36, 마무리 15구면 +6) |

- 피로가 70 이상인 채로 경기에 나가면 경기 뒤 컨디션이 한 칸 내려갈 수 있다(5.5).
- 투수의 경우 경기 중 지치는 효과(기존 `fatigue.js`의 피로와 체력)와 육성 피로는 **별개**다.
  - 경기 중 지침은 기존 엔진 그대로 투구 수와 체력으로 정한다.
  - ★ 육성 피로가 높아도 경기 시작 능력치를 깎지는 않는다. 영향은 컨디션을 통해서만 준다.
  - 이유: 효과를 한 경로로 모아야 밸런스를 잡기 쉽다.

### 5.5 컨디션(기세)

- ★ 5단계가 있다: 최악(−2) · 나쁨(−1) · 보통(0) · 좋음(+1) · 최상(+2).
  - 새로 키우기는 보통에서 시작한다.
  - 화면에서는 아이콘과 글자로 보여 준다(⬇⬇ ⬇ ➖ ⬆ ⬆⬆).
- **경기 뒤 변화.** 내 선수의 그 경기 점수로 정한다.
  - ★ 타자 점수: 안타 +1, 장타 +1 추가, 홈런 +1 추가, 볼넷 +0.5, 타점 +0.5, 삼진 −0.5, 범타 −0.3
  - ★ 투수 점수: 아웃 하나 +0.3, 탈삼진 +0.2, 자책 −1
  - 점수가 높으면 한 칸 오르고, 낮으면 한 칸 내려간다. 중간이면 그대로다.
  - 경계값은 평균 선수가 평범한 경기를 했을 때 그대로 유지되도록 잡는다. 예: 타자 2 이상 ↑, −1 이하 ↓.
  - 피로 70 이상으로 출전했으면 한 칸 더 내려간다(최악 아래로는 안 간다).
  - 휴식을 고르면 컨디션이 보통 쪽으로 한 칸 다가간다. 최악에서 빨리 벗어나는 길이다.
- **경기 중 효과** (★ 작게):
  - 타자: 배트 크기 ×(1 + 0.04·c), 타구질 +0.015·c
  - 투수: 제구 +2·c, 구속 +1·c (km/h)
  - c는 −2 ~ +2이고, 효과는 내 선수에게만 준다.
  - 경기 화면 내 선수 이름 옆에 컨디션 아이콘을 보여 준다.

### 5.6 특성

- 얻는 방법은 두 가지다.
  - **훈련:** 같은 특훈을 정해진 횟수만큼 하면 생긴다. ★ 4번이다.
  - **경기:** 누적 기록이 기준을 넘으면 생긴다.
- 한 번 얻은 특성은 사라지지 않는다.
- ★ 나쁜 특성은 넣지 않는다.
- 효과는 해당 상황에서만, 내 선수에게만, 작게 준다.
  - ★ 타자: 배트 크기 ×1.08과 타구질 +0.03 정도
  - ★ 투수: 제구 +6 정도

| 특성 | 대상 | 얻는 법 | 효과가 나는 상황 |
|---|---|---|---|
| 찬스에 강함 | 타자 | 득점권 대비 특훈 4번 · 또는 득점권 안타 누적 8개 | 주자 2·3루 |
| 좌투수 킬러 | 타자 | 좌투수 대비 특훈 4번 · 또는 좌투수 상대 안타 누적 10개 | 상대가 좌투수 |
| 초구 공략 | 타자 | 초구 공략 특훈 4번 | 0-0 카운트 |
| 거포 본능 | 타자 | 홈런 누적 10개 | 그 경기에서 이미 홈런을 친 뒤(장타 쪽 타구질만 더) |
| 끈질김 | 타자 | 볼넷 누적 12개 | 2스트라이크 이후(배트 크기만) |
| 위기관리 | 투수 | 위기 대비 특훈 4번 · 또는 득점권 무실점 탈출 누적 10번 | 주자 2·3루 |
| 좌타자 킬러 | 투수 | 좌타자 대비 특훈 4번 · 또는 좌타자 상대 탈삼진 누적 15개 | 상대가 좌타자 |
| 결정구 | 투수 | 결정구 특훈 4번 · 또는 탈삼진 누적 30개 | 2스트라이크(구속 +2, 제구 +4) |
| 강철 어깨 | 투수 | 체력 90 이상이고 선발 6이닝 이상 누적 5번 | 경기 중 지침이 느리다(투구 수 계산 ×0.85) |
| 뒷문 지킴이 | 투수 | 세이브 누적 8개 | 9회 이후 |

- "누적"은 육성 슬롯 전체 통산이다. 시즌이 바뀌어도 이어진다.
- 특성을 얻으면 결과 화면에 크게 알린다. 선수 카드에는 배지로 보여 준다.

### 5.7 경기 진행: 내 장면만 직접

경기는 기존 `js/ui/game.js`의 `showGame`을 그대로 쓴다. 새 옵션 `raise`를 받는다.

```
raise: { kind: 'bat' | 'pitch', playerId, role: 'SP' | 'CL', perks }
```

`raise`가 없으면 지금과 100% 같게 동작해야 한다.

**타자**

- 삼성이 홈이고, 공격은 말이다.
- 내 선수의 타석이 아닐 때는 자동으로 빠르게 넘긴다.
  - 기존 `simulateUntil`을 쓴다. 조건은 "내 선수 타석이 됐거나 경기가 끝났다"이다.
  - 넘긴 뒤에는 기존 메시지 띠로 한 줄만 보여 준다. 예: "4회말까지 진행 · 2-1, 1사 1루"
  - 그다음 내 타석을 바로 시작한다.
- 상대 공격(초)도 모두 자동이다.
- ★ 타순: 기본 9명 안에 있는 선수는 그 자리 그대로 들어간다.
  - 벤치 선수(이성규, 전병우, 김헌곤)는 지명타자 자리(최형우 자리)에 들어간다.
- ★ 교체 규칙: 7회 이후 내 타석 차례가 왔을 때 두 조건을 모두 만족하면 대타로 바뀐다.
  - 컨디션이 나쁨 이하다.
  - 그 경기 무안타이고 삼진 2개 이상이다.
- 교체되면 "대타로 교체됐어요"를 보여 주고 남은 경기를 자동으로 끝낸다.

**선발투수**

- 1회초부터 상대 공격을 내가 직접 던진다. 말 공격은 자동이다.
- 강판은 기존 컴퓨터 교체 규칙과 같은 기준이다(`cpuMaybeChangePitcher`의 피로 0.6).
- ★ 한 이닝에 5실점 이상이면 그 이닝 뒤에 강판한다.
- 강판되면 "강판" 메시지를 보여 주고 남은 경기를 자동으로 끝낸다.
- 경기 메뉴의 투수 교체는 "스스로 강판"으로만 쓰인다.

**선발 등판 간격** (사용자 결정: "4경기마다")
- 4경기마다 한 번 선발로 나간다. 새 시즌은 1경기째에 선발한다.
- 사이의 3경기는 내 장면 없이 자동으로 끝난다.
  - 그날마다 선택(훈련 또는 휴식)은 1번씩 하고, 허브에서 "경기 진행(등판 없음)"으로 넘긴다.
- 한 시즌 27경기면 선발 7번이다.
- 내 선발 날에는 `season.js` 로테이션 대신 내 선수를 선발로 넘긴다(`userStarterId`).
- 다른 날의 삼성 선발은 내 선수를 뺀 SP 순서로 돌린다.

**마무리**

- 8회말이 끝났을 때 점수 차가 3점 이하면 9회초에 등판한다. 앞서든 뒤지든 동점이든 같다.
- ★ 연장이면 10회초까지 던진다.
- 그 밖의 경기는 등판 없이 자동으로 끝내고 "오늘은 등판이 없었어요"를 보여 준다.

**모든 경우 공통**

- 수비 조작(`prefs.fielding`)과 경기 화면 설정(난이도, 가이드)은 기존 그대로다.
- 상대 팀, 상대 선발, 삼성의 나머지 선수는 `rosters.js`의 원래 능력치를 쓴다.
  - 시즌모드 성장분은 반영하지 않는다.
- 내 선수만 육성 능력치, 컨디션, 특성을 적용받는다.
- ★ 삼성의 다른 투수는 매 경기 쌩쌩한 상태로 시작한다.
  - 기존 `fatigue.js`의 경기 간 피로는 육성모드에서 쓰지 않는다.

### 5.8 경기 엔진 연결 (기존 모드를 바꾸지 않는 방법)

- 컨디션과 특성 효과는 match 객체에 `perks` 필드가 **있을 때만** 작동한다.
  - 기존 `heat` 필드와 같은 방식이다.
  - 다른 모드는 `createMatch`에 `perks`를 넘기지 않으므로 결과가 바뀌지 않는다.
- 효과 계산은 `js/core/perks.js` 한 곳에 둔다.
  - 이 함수는 순수 함수이고 rng를 쓰지 않는다. 그래서 기존 rng 순서가 바뀌지 않는다.
  - 타자 쪽: `perkBoost(m, batterId)` → `{ reach, quality }`
  - 투수 쪽: `perkPitcher(m, pitcher)` → 제구와 구속이 조정된 투수
- 연결 지점:
  - 타자: 기존 `heatBoost`를 쓰는 세 곳(`match.js` 82행, `game.js` 329행·1189행)을 한 함수로 묶는다. 예: `boostFor(m, batterId, side)` = heat와 perks를 곱하고 더한 값. 기존 상한은 유지한다.
  - 투수: `matchup(m)`이 돌려주는 `pitcher`에 `perkPitcher`를 적용한다. 그러면 core(공 계산)와 UI(게이지 초록 폭)가 같은 값을 본다.
- 테스트로 확인한다.
  - `perks`가 없는 경기는 같은 씨앗에서 고치기 전과 로그가 똑같다.
  - 기존 balance 테스트가 그대로 통과한다.

### 5.9 시즌과 순위

- 기존 `season.js`를 그대로 쓴다.
  - `createSeason({ cycles: 3, innings: 9 })` → ★ **27경기**(나머지 9개 팀과 3번씩)
  - 앞서 말한 "30경기"는 일정 구조상 27경기가 된다.
  - `recordRound`, `standings`도 그대로 쓴다. 삼성 경기 결과를 넘기면 다른 팀 경기는 시뮬레이션된다.
- ★ 포스트시즌은 없다.
  - `recordRound`가 phase를 'post'로 바꾸는 순간 육성 쪽에서 시즌 종료로 처리한다.
- 시즌 종료 화면에는 다음을 보여 준다.
  - 내 선수 시즌 성적
  - 팀 순위와 승패
  - 이번 시즌에 오른 능력치 합계, 얻은 특성
- 시즌 종료 화면에서 "다음 시즌"을 누르면 연도가 +1 되고 새 일정이 시작된다.
  - 시즌 성적과 순위는 새로 시작한다.
  - 능력치, 특성, 컨디션, 피로, 통산 기록은 이어진다.
- ★ 시즌 사이에 피로는 0으로, 컨디션은 보통으로 되돌린다(비시즌 휴식).
- 내 선수 성적은 `growth.js`의 `playerLine` 계열 함수로 계산한다.
  - 타자: 타율·안타·홈런·타점·OPS
  - 투수: 평균자책점·이닝·탈삼진·승·세이브
  - 경기 경험치는 기존 `gainFromLog`의 표를 내 선수에게만 적용해서 쌓는다.
- ★ 기록 화면 하나를 둔다. 시즌별 한 줄 기록, 통산, 특성 목록이 들어간다.

### 5.10 저장 형식

```
localStorage['baseball.raise.v1'] = { v: 1, slots: [slot | null, slot | null, slot | null] }
slot = {
  playerId, kind: 'bat' | 'pitch', role: 'SP' | 'CL' | null,
  growth,                // growth.js 형식(xp, delta) — 내 선수 한 명만 쓴다
  condition: -2..2, fatigue: 0..100,
  traits: [id], progress: { train: { 특훈id: 횟수 }, feat: { 누적 카운터 } },
  year, season,          // season.js 상태
  chosen: bool,          // 오늘 선택을 했는지
  seasonLog: [...],      // 이번 시즌 내 선수 타석/투구 기록(성적 계산용, 내 선수 것만)
  total: {...}, history: [{ year, line, rank, w, l, d, traits: [새로 얻은 것] }],
}
```

- 읽다가 손상되었으면 그 슬롯만 비운 것으로 처리하고 화면에 알린다. 다른 슬롯은 살린다.
- 저장에 실패하면 시즌모드처럼 "저장 안 됨" 표시를 한다.
- 용량: 내 선수 기록만 남기므로 시즌당 수 KB 이내다.
  - 일정(schedule)은 시즌마다 다시 만든다. 통산은 `total`에 합쳐 둔다.

## 6. 빌더에게 맡기는 것

- 화면 배치와 문구 세부는 기존 허브와 결과 화면 스타일(`hub.js`의 클래스)을 따르면 된다.
- 5.3~5.6의 숫자(경험치, 피로, 컨디션 경계, 특성 기준과 효과)는 출발값이다.
  - 시뮬레이션으로 아래 7절 목표에 맞게 조정해도 된다.
  - 조정했으면 최종 값을 커밋 메시지에 적는다.
- 내 장면까지 넘길 때의 메시지 표시 방식(띠, 시간)은 기존 넘기기(`skip`) 연출을 따른다.

## 7. 확인 방법

**core 테스트** (먼저 쓴다)

- 훈련
  - 능력치가 오르고 피로가 쌓인다.
  - 피로가 넘치는 훈련은 거부된다.
  - 높은 능력치일수록 덜 오르고, 상한을 넘지 않는다.
- 휴식, 자연 회복, 출전 피로
- 컨디션
  - 좋은 경기면 ↑, 나쁜 경기면 ↓
  - 피로 70 이상이면 추가로 ↓
  - 범위를 벗어나지 않는다.
- 특성
  - 특훈 4번이나 누적 기준을 넘으면 생긴다.
  - 중복으로 생기지 않는다.
  - 상황 밖에서는 효과가 0이다.
- `perks`가 없는 경기
  - 같은 씨앗에서 `simulateGame` 결과와 로그가 고치기 전과 같다.
  - 테스트에 고정 씨앗 몇 개의 기대값을 박아 둔다.
- `perks`가 있으면 해당 선수, 해당 상황에서만 boost와 제구가 바뀐다.
- 시즌
  - 27경기 뒤 종료된다.
  - 다음 시즌에 성적은 0부터, 능력치와 특성은 유지된다.
- 저장
  - 왕복 저장이 된다.
  - 손상된 슬롯 하나가 다른 슬롯을 망치지 않는다.
  - 시즌모드 키(`baseball.career.v1`)를 건드리지 않는다. 가짜 storage로 확인한다.
- 밸런스 시뮬레이션 (자동으로 친다고 가정)
  - 같은 타자를 "파워만 훈련" vs "훈련 안 함"으로 3시즌 돌리면 홈런 수가 눈에 띄게 차이 난다.
  - 한 시즌 만에 능력치가 +15 넘게 오르지 않는다.

**전체 테스트**

- `node --test "tests/*.test.mjs"`를 돌린다.
- 기존 테스트, 특히 balance, season, career, versus가 그대로 통과해야 한다.

**브라우저 확인**

- 확인 방법: headless Chrome으로 `#raise`에 들어가 슬롯을 만들고, 타자·선발·마무리 각각 한 경기씩 진행한다.
  - 내 장면만 조작 화면이 나오는지
  - 나머지가 자동으로 넘어가는지
  - 결과가 저장되는지
- 시즌모드와 대결모드에 들어가서 이전과 똑같이 시작되는지도 본다.
- 확인하지 못한 부분은 숨기지 않고 보고한다.
